# CM530_ROS_BRIDGE

**本專案提供 ROS 主機與兩支 AX-12A 手臂之間的 CM-530 直接轉接韌體。** 現行版本為 [16 CM530 DUAL ARM](16%20CM530%20DUAL%20ARM/README.md)，使用主機序列協定 **4**。

CM530 接收 ROS 已算好的四軸位置整數，驗證後送往指定手臂，回覆傳送結果；也接收 ROS 的 LED 顯示命令。運動計算、排程、視覺與任務流程全部留在 ROS 端。此儲存庫提供韌體、手動終端、離線測試與對接規格，不提供 ROS 節點。

## 系統架構

現行系統依「雙機械手臂協同搬運系統」架構運作：

**A 站供料 → 手臂 1 → B 站交接 → 手臂 2 → C 站八格排列。**

| 模組 | 責任 | 本儲存庫交付 |
|---|---|---|
| 環境相機／視覺 | 由上往下觀測桌面，判斷 A、B 站是否有物品，提供全域場景 | 否 |
| 兩臂手眼相機／視覺 | 物品 3D 定位、抓取前定位、放置前再確認與 C 站格位辨識 | 否 |
| Jetson／ROS 任務協調器 | 任務排程、四狀態 FSM、B 站互斥、C 站格位管理、監控與異常處理 | 否 |
| ROS 運動規劃 | 座標轉換、IK、關節校正與限位、軌跡取樣、時間及完成判斷 | 否 |
| ROS 序列轉接模組 | 獨占 CM530 序列埠，序列化命令並核對回覆 | 僅提供規格 |
| CM530 | 命令驗證、手臂路由、四軸目標／torque 封包、LED GPIO、ACK／ERR | 是 |
| ESP32／吸盤控制 | 電磁閥、吸取與釋放，由 ROS 經另外介面協調 | 否 |

硬體路徑保留：相機資訊進入 Jetson AGX Orin／ROS；ROS 透過一個序列埠控制 CM530，再由 CM530 的共用 TTL bus 控制八顆 AX-12A。吸盤經外部 ESP32 控制，不經 CM530。這是功能分工，不表示已交付 micro-ROS 移植或特定 ROS topic/service/action。

## ROS 端的任務流程

| 狀態 | 手臂 1：A → B | 手臂 2：B → C |
|---|---|---|
| 0 Idle | 等待 A 站有可取物品 | 等待 B 站有可取物品及 C 站有可用格位 |
| 1 Pick | 定位並到 A 站吸取 | 取得 B 站使用權，定位並吸取 |
| 2 Place | 取得 B 站使用權，前往 B 站放置 | 前往已選定的 C 站空格放置 |
| 3 Return | 返回 ROS 設定的待機姿態，再回 Idle | 返回 ROS 設定的待機姿態，再回 Idle |

這四個狀態只存在 ROS；韌體不接收 state、Pick、Place 或 Return 命令。

**B 站互斥：** ROS 必須管理唯一持有者，在手臂進入共享工作區前取得鎖，確認手臂實際離開後才能釋放。不能只靠看到物品或收到 CM530 ACK 就釋放鎖。發生逾時或位置不明時，停止原流程並由上層判斷共享區是否仍被占用。

**C 站八格：** 固定 2 × 4、編號 1～8。ROS 依手眼相機資訊辨識占用，從可用且未被預留的格位選編號最小者，計算放置位置，放置後再確認占用；所有八格確認已滿時回報排列完成。實際格號方向、座標與機構姿態由 ROS 校正設定。現行任務是格位排列，不沿用舊圖的形狀分類規則。

## 通訊與硬體映射

| 手臂 | j1 | j2 | j3 | j4 |
|---|---:|---:|---:|---:|
| arm1 | 17 | 3 | 2 | 15 |
| arm2 | 12 | 1 | 8 | 16 |

j1～j4 沿用既有由下到上的關節順序。

- 主機 ↔ CM530：單一序列埠，57600 baud／8N1／無流量控制；主機 UART 為 USART3。
- CM530 ↔ 馬達：USART1、共用 TTL bus、1 Mbps、Dynamixel Protocol 1.0。
- 主機命令：ASCII 文字行；每軸原始整數 0～1023，建議 LF 結尾。
- 馬達 ID、EEPROM、既有速度、零位與機械範圍不由本韌體修改。
- **主機協定版本與馬達協定分開；馬達仍使用 Dynamixel Protocol 1.0。**

## 第 16 版支援的操作

| 命令 | 成功回覆 |
|---|---|
| `PING` | `PONG` |
| `VERSION` | `VERSION,4` |
| `AX,arm1,512,512,512,512` | `OK,AX,arm1` |
| `TORQUE,arm1,0` | `OK,TORQUE,arm1,0` |
| `TORQUE,arm1,1` | `OK,TORQUE,arm1,1` |

arm2 使用相同格式。AX 必須提供四個值，不能省略手臂或只提供單一位置。

開機只對兩臂各傳一次 torque-off，兩筆傳送成功後輸出 `READY,4`。初始化失敗鎖住動作命令直到重啟，但 PING／VERSION／LED 仍可使用。開機及每次 torque-off 後，必須先成功 AX 設定目標，才允許明確 torque-on；AX 不會自動開啟 torque。

`HOME/HOLD/BEGIN/PT/END/STOP` 都不支援。ROS 自行管理姿態、軌跡點與時間，逐筆送 AX；韌體不記錄軌跡、不發送 READ、不提供位置或到位回報。

**馬達 ACK／READY 只證明本地處理與封包傳送，LED ACK 只表示 GPIO 已設定，都不證明馬達到位或實際 torque 狀態。** 沒有位置回讀就不能以重送最後目標取代當前位置保持；torque-off 是卸力，也不是保持位置。本版沒有斷線自動停機或自動卸力。

## 每臂 LED 顯示

| 手臂 | MOVING：綠燈 | STOPPED：紅燈 |
|---|---|---|
| arm1，左欄 | MANAGE／PB13 | PROGRAM／PB14 |
| arm2，右欄 | TX／PC14 | RX／PC15 |

應用韌體啟動後雙紅待命。ROS 使用 `LED,arm1,MOVING` 或 `LED,arm1,STOPPED` 設定 arm1，arm2 同理。每臂同時只亮一顆；PLAY、AUX 熄滅，POWER 不變。TX／RX 在本韌體中顯示 arm2 狀態，不代表通訊收發。

ROS 在準備動作時送 MOVING，依自己的完成判斷確認停止後送 STOPPED。燈號只表示主機最後通知的狀態；STOPPED 不是停止馬達的指令。AX／TORQUE 不自動改燈，demo、退出、錯誤與斷線也不追加 LED 命令；斷線後可能保留舊顯示。

終端正常 LED 收發不印 TX／RX 文字，也不增加狀態顯示；線上 ACK 仍存在並嚴格核對。LED 的錯誤、逾時、錯配 ACK 或重啟仍會顯示錯誤並停止後續發送。其他命令輸出照常。

## 第一次使用

1. 確認八顆馬達 ID、1 Mbps、供電與接線；由實際機構確認允許的四軸目標。512 只是原始數值，不是已校正的待機姿態。
2. 依第 16 版 README 完整建置、檢查並燒錄新版映像。
3. 關閉其他占用序列埠的程式，啟動終端：

```powershell
cd "16 CM530 DUAL ARM"
python -m pip install -r requirements.txt
python manual_position_terminal.py --port COM4
```

4. 終端核對 `VERSION,4` 及 `PONG`；使用適合機構的四軸 AX 目標，再明確送 TORQUE,1。COM4 請換成實際裝置。
5. 驗收單臂小幅動作、卸力與雙臂交替命令後，再由 ROS 接管。手動終端與 ROS 不可同時開啟該埠。

整條序列連線必須全域一問一答。ERR、逾時、錯配 ACK 或板子重啟後停止後續發送，不自動重送動作或追加 torque-off。
